# 運動記録Webアプリ

iPhoneで生活・運動・身体データを入力し、Apple Numbersへ貼り付けるための個人用Webアプリです。HTML・CSS・JavaScriptで動作する静的アプリで、入力データをサーバーへ送信しません。

Version 0.2を段階的に開発中です。JSONバックアップ書き出しは公開済み、復元はローカル実装・PCテスト済みでiPhone実機確認待ちです。Numbers CSV取り込みは未実装です。

- 公開アプリ：[https://tatsu568.github.io/exercise-record/](https://tatsu568.github.io/exercise-record/)
- GitHubリポジトリ：[tatsu568/exercise-record](https://github.com/tatsu568/exercise-record)
- 今後の開発予定：[ROADMAP.md](ROADMAP.md)

## ふだんの使い方

1. iPhoneのホーム画面から「運動記録」を開きます。
2. 日付を確認し、生活・運動・散歩・身体データを入力します。入力は変更のたびに端末内へ自動保存されます。
3. Numbersへ貼り付ける場合は「運動データコピー」または「身体データコピー」を押します。ChatGPTへ週次報告する場合は「週間運動コピー」または「週間身体コピー」を押します。
4. Numbersで貼り付け先セルを選択し、ペーストします。週間コピーの結果はChatGPTの入力欄に貼り付けます。

コピーできると「コピーしました」と一時表示されます。Numbersファイルへの直接書き込みは行わず、コピーしたデータをNumbersへ貼り付けます。

### 入力項目

- **日付**：初期値は端末の今日の日付です。カレンダーで選ぶほか、「前」「次」で1日ずつ移動できます。過去・未来の日付を選べます。
- **生活**：出社・在宅・休日は1つだけ選択でき、選択中のものを再度タップすると解除できます。「子供と動く」は勤務区分と独立して切り替えます。
- **スタンディング**：5〜20を1刻みで選びます。初期値は10です。
- **スクワット**：±5回・±10回で増減します。0回未満にはなりません。Numbersでは5回につき「○」1個に変換されます。0回は空欄です。
- **足踏み**：0〜2回を1回ずつ増減します。スクワットの「−5」「＋5」と同じ列にボタンが来るよう配置しています。Numbersでは1回につき「○」1個、0回は空欄です。
- **プランク**：±30秒・±60秒で増減します。0秒未満にはなりません。Numbersでは30秒につき「○」1個、0秒は空欄です。
- **散歩**：分・秒・距離（km）・歩数を個別に入力できます。入力は任意で、歩数だけでも記録できます。明示的に入力した0は保持し、未入力欄は空欄にします。Numbersでは例として `24分39秒 1.89km 2320歩` のように1セル分のテキストにまとめます。
- **身体データ**：体重・体脂肪率・基礎代謝は任意入力です。未入力は空欄、明示的に入力した0は0としてコピーします。

### キーボード操作

散歩は「分 → 秒 → 距離 → 歩数 → 完了」、身体データは「体重 → 体脂肪率 → 基礎代謝 → 完了」の順に「次へ」で移動できます。各グループの最後で「完了」を押すとキーボードを閉じます。

### Numbersへのコピー形式

クリップボードへHTMLテーブルとタブ区切りプレーンテキスト（TSV）の両方をコピーします。CSVファイルは作成しません。日付・曜日はコピーに含めません。

| ボタン | 列数・順番 |
| --- | --- |
| 運動データコピー | 9列：出社、在宅、休日、子供と動く、スタンディング、スクワット、足踏み、プランク、散歩 |
| 身体データコピー | 3列：体重、体脂肪率、基礎代謝 |
| 週間運動コピー | 見出しを含む10列：日付、出社、在宅、休日、子供と動く、スタンディング、スクワット、足踏み、プランク、散歩。選択日より前の週（月曜〜日曜）の7日分 |

ON項目は「○」、OFF項目は空欄です。スクワット・足踏み・プランクも指定単位ごとの「○」に変換し、0は空欄になります。未入力の散歩・身体データは空欄を保ちます。HTMLテーブルにコピー元のフォントや背景色の指定は加えていませんが、貼り付け時の表示はiOSとNumbersのバージョンによって異なるため、実機で確認してください。

週間運動コピーのボタン直下には、実際にコピーする前週（月曜〜日曜）の対象期間が表示され、日付を変更すると表示も更新されます。選択日が属する週のひとつ前の月曜日〜日曜日を対象に、見出し行と日付順の7行をタブ区切りプレーンテキストでコピーします。期間が年をまたぐ場合は日付に年を付けます。記録のない日は日付以外を空欄にし、表の後ろに「未記録日：…」と表示します。保存済みだが運動をしていない日は保存値に基づいて出力されます。この操作は既存のlocalStorageを読み取るだけで、記録を作成・変更しません。週間運動コピーはNumbers向けHTMLテーブル方式ではなく、プレーンテキストを使用します。

週間身体コピーは、同じ対象期間から体重・体脂肪率・基礎代謝のいずれかが入力された最も新しい日付を1件選び、日付と見出しを含む4列のタブ区切りテキストとしてコピーします。採用日の未入力項目は空欄のままにし、古い記録の値で補いません。対象期間に身体データがない場合は、その旨のメッセージをコピーします。保存データは読み取り専用です。

## データ保存と運用方針

記録はブラウザの `localStorage` に日付ごとに自動保存され、同じ保存領域で同じ日付を開くと復元されます。現在、主な入力方法はホーム画面から起動するWebアプリです。iOSの動作条件によりSafariとホーム画面アプリの保存領域が別になる場合があるため、両方を使う場合は別々に確認してください。

現時点ではNumbersが全履歴を保持する正本で、Webアプリは入力補助として使い、必要な記録をNumbersへコピーします。将来はNumbersの過去データをWebアプリへ移行し、Webアプリをメイン、Numbersをバックアップにする構想です。詳細は [ROADMAP.md](ROADMAP.md) を参照してください。

クラウド同期・iCloud同期はありません。アプリやホーム画面アイコンの削除、Safariのサイトデータ消去、端末・ブラウザ環境の変更などにより、端末内の記録が失われる可能性があります。定期的にJSONバックアップを書き出し、Numbersの元データも保管してください。ローカル開発用HTTP、GitHub Pages、Safari、ホーム画面アプリは保存元が異なることがあります。ローカルで入力した記録が公開版へ自動で移ることはありません。

### JSONバックアップの書き出し

「バックアップ保存」を押すと、現在開いているSafariまたはホーム画面アプリの保存領域にある全日付の記録を、`運動記録バックアップ_YYYY-MM-DD.json` という名前のJSONファイルとして書き出します。iPhoneで共有シートが開いた場合は「ファイルに保存」を選び、保存先を選択してください。ブラウザのダウンロードが始まった場合は、ダウンロード項目やファイルアプリで保存結果を確認してください。画面のメッセージは保存操作の開始を示すもので、ファイルが保存先に残ったことまでは確認できないため、実際のファイルを確認してください。

バックアップには形式名・形式バージョン・書き出し日時と日付別記録が含まれます。空欄と明示入力の0を含め、保存内容を読み取り専用で書き出します。保存JSONが破損している、または日付・項目の型が想定外の場合は書き出しを中止し、既存記録を修復・削除・初期化しません。Numbersの元データも引き続き保管してください。

### JSONバックアップからの復元（Version 0.2）

1. 復元先のSafariまたはホーム画面アプリで「バックアップ復元」を押し、書き出したJSONを選びます。Safariとホーム画面版の保存領域が異なる場合があるため、復元先を確認してください。
2. 作成日時、記録日数・期間、新規・一致・競合・エラー・警告を確認します。この段階では保存データを変更しません。通常入力と日付移動は、プレビューを閉じるまで一時停止します。
3. 競合する日付を開いて差分を確認します。初期選択はすべて「既存を維持」です。必要な日付だけ「バックアップで置換」を選びます。置換は日付全体に対して行い、空欄も含めて置き換えます。古い値で空欄を補完する処理はありません。
4. 「① 復元前バックアップを保存」を押し、現在の全記録を別のJSONとして保存します。共有シートをキャンセルした場合は先へ進めません。共有・ダウンロードの開始だけでは保存完了を保証できないため、ファイルアプリ等でファイルを確認してから「②」をチェックします。
5. 追加・置換・スキップ件数と保存前後の日数を確認し、「③」をチェックします。競合の選択を変更すると、この最終確認は解除されます。
6. 「確認して復元を実行」を押し、確認ダイアログで確定します。保存直前に現在のデータを再確認し、プレビュー後に変更されていれば復元を停止します。
7. 全候補を一度の書き込みで保存し、読み戻した全項目・件数を照合した結果を表示します。表示中の日付も保存結果から読み直します。

「閉じる・キャンセル」、ファイル選択の取り消し、最終確認の取り消しでは、既存データを変更しません。空バックアップや完全一致など、反映する変更がない場合も書き込みません。復元中の画面を閉じると未確定の選択は破棄されます。

対応形式は `format: "exercise-record-backup"`、数値の `formatVersion: 1`、書き出し機能が生成するUTCのISO作成日時、日付別 `records` です。実在日付、型、運動の範囲・単位、散歩・身体の有限な非負数文字列（散歩の分・秒・歩数は整数、秒は0〜59）を検証します。数値を正規化せず `""` と `"0"` を保持します。不足する既知項目は比較時だけ現行既定値を使い、保存時には補完しません。未知の日別項目は警告して保持し、未知の最上位メタデータ・未対応版・重複JSONキー・不正値は全体停止します。既存の破損データも強制上書きしません。

保存失敗時に既存キーを削除したり、日付ごとに部分保存したりしません。保存後の照合に失敗した場合は、他の画面の変更を消さないよう自動巻き戻しを行わず、入力・再保存を停止します。復元前JSONを保管し、プレビューを閉じて現在の記録を確認してください。単一キーへの書き込みで途中反映を減らしていますが、保存中のアプリ終了後は保存結果を確認してください。

**復元中は、同じ保存領域を使う別タブ・別画面で入力しないでください。** 保存直前の再照合と `storage` 通知で変更を検出しますが、localStorageには他画面を含む比較・書き込みを一括で保証する機能がありません。復元前JSONは結果確認が終わるまで保管してください。Numbers CSVの取り込みは未実装です。

### 復元機能の検証

PCの自動テストは、架空データとモック保存領域のみで実施します。Node.jsがある場合、プロジェクトフォルダーで次を実行できます。アプリの使用・Pythonによる起動にはNode.jsは不要です。

```cmd
node --test tests/record-transfer.test.cjs tests/restore-ui.test.cjs
```

iPhone実機では、公開版の記録を使わず、未使用ポート等の別のローカル保存領域で架空の記録を作って検証してください。ファイル選択、差分表示・競合選択、復元前JSONの保存と確認、各段階のキャンセル、復元後の再起動と記録維持、従来の4コピー・日付移動を確認します。Safariとホーム画面PWAの実際のファイル操作・狭い画面での表示は、PCのモックテストでは確認できません。

## Windowsでローカル確認（Pythonを使う方法）

Pythonの標準機能だけを使います。Node.jsのインストールは不要です。

1. エクスプローラーで `運動記録Webアプリ` フォルダを開きます。
2. エクスプローラー上部のアドレスバーをクリックし、`cmd` と入力してEnterを押します。プロジェクトフォルダをカレントフォルダにしたコマンドプロンプトが開きます。
3. 次を実行します。

   ```cmd
   py -m http.server 8080 --bind 0.0.0.0
   ```

   `py` が使えない場合は、次を試してください。

   ```cmd
   python -m http.server 8080 --bind 0.0.0.0
   ```

4. PCのブラウザで <http://localhost:8080> を開きます。
5. 終了するときは、サーバーを起動したコマンドプロンプトで `Ctrl+C` を押します。

### iPhoneからローカル版を確認する

1. Windows PCとiPhoneを同じWi-Fiに接続します。
2. PCで上記のPythonサーバーを起動したままにします。
3. もう1つコマンドプロンプトを開き、`ipconfig` を実行します。
4. 使用中のWi-Fi接続にある `IPv4 Address` を確認します。
5. iPhoneのSafariで `http://PCのIPv4アドレス:8080` を開きます。たとえば、IPv4アドレスが `192.168.1.25` なら `http://192.168.1.25:8080` です。このIPアドレスは説明用の例で、実際のアドレスはPCやネットワークごとに異なります。
6. 接続できない場合は、PCのサーバーが起動中か、PCとiPhoneが同じWi-Fiか、入力したIPv4アドレスが正しいかを確認します。WindowsファイアウォールがPythonの通信を確認したら、プライベートネットワークで許可します。公共Wi-Fiの端末間通信制限がある場合は接続できないことがあります。

Node.jsが既にインストールされている場合は、プロジェクトフォルダのコマンドプロンプトで `node server.js` を実行しても確認できます。停止は同じコマンドプロンプトで `Ctrl+C` です。Node.jsの導入は必須ではありません。

### ローカルHTTPでの制約

PC内の `localhost` と異なり、iPhoneからLAN内のIPv4アドレスへ接続する場合はHTTPです。HTTPSが必要なService WorkerやClipboard APIは利用できない場合があり、コピー処理もブラウザの代替経路に制限されることがあります。ローカル版では主にレイアウト、ボタン操作、日付別保存を確認してください。Numbersへの貼り付けとホーム画面アプリの最終確認は、GitHub PagesのHTTPS環境で行ってください。ローカル版と公開版の保存データは別です。

## GitHub Pagesの更新手順

現在のサイトはGitHub Pagesで公開済みです。通常の更新では初期化やリモート追加は不要です。

- リポジトリ：<https://github.com/tatsu568/exercise-record>
- 公開URL：<https://tatsu568.github.io/exercise-record/>

プロジェクトフォルダでコマンドプロンプトまたはPowerShellを開き、作業後に次の流れで更新します。差分を確認し、必要なファイルだけを `git add` してください。例ではREADMEだけを追加しています。

```cmd
git status --short --branch
git diff --check
git diff

git add README.md
git diff --cached --stat
git commit -m "Update README"
git fetch origin
git status --short --branch
git push origin main
```

push前に現在のブランチが `main` で、`origin/main` に意図しない先行変更がないことを確認してください。競合や予期しないリモート変更があれば、状態を確認せずに強制pushしないでください。認証が必要な場合はGitHub公式のサインイン画面を使い、パスワードやトークンを共有しないでください。

push後はリポジトリの **Actions** タブで最新のPagesデプロイが成功したことを確認します。Pagesの公開元はGitHub Actionsです。デプロイ完了後、公開URLを開き、iPhoneでも再読み込みまたはアプリを開き直して最新版を確認します。表示が古い場合は少し待って再度開き直してください。サイトデータの消去はローカル記録を失う可能性があるため、更新確認のために消去しないでください。

## コード確認と実機確認の区別

直近のコード確認では、JavaScriptとService Workerの構文チェック、および `git diff --check` が成功しています。これらは構文・差分の確認であり、iPhoneやNumbersでの動作確認を代替するものではありません。上のチェックリストはGitHub Pages更新後に利用者が実機で確認する項目です。

アプリ本体は外部ライブラリを使わないHTML・CSS・JavaScriptです。`index.html` が入力画面、`style.css` が表示とレイアウト、`script.js` が入力・保存・コピー、`manifest.json` がホーム画面追加用の設定、`service-worker.js` が静的ファイルのキャッシュ、`icons/` がアプリアイコンを担当します。`server.js` はNode.jsを使う場合の補助サーバーです。
