# Numbersデータ変換仕様 v0.1

作成目的：Numbersから書き出した運動記録ファイルを、運動記録Webアプリの既存保存形式へ安全に変換するための調査・設計資料。

## 状態の表記

- **確認済み**：調査したファイル構造または現行コードで確認した事実。公開版には個人記録の値・日付対応を記載しない。
- **設計案**：実装時に採用を推奨する方法。未実装であり、確定仕様ではない。
- **未確認・要決定**：実データの範囲外、または利用者との合意が必要な事項。

## 個人データの取り扱い

- 個人の実記録を使う照合・テストは、Git管理外のローカル環境で行う。
- 実ファイル、実データCSV、日付と値が結び付いた結果一覧、検証ログはコミットしない。
- 本書の散歩入力例はすべて架空のテストデータであり、実記録の一覧ではない。
- 調査対象の実ファイル名、実日付と値の組み合わせ、身体測定値は本書に含めない。

## 2. 列と保存フィールドの対応表

現行コードで確認した保存キーは `exercise-record.entries.v1` です。保存値は日付キーから日別レコードを引くオブジェクトです。検証後、既存フィールドへ変換する案です。

| 移行元 | 保存フィールド | 変換仕様案 |
|---|---|---|
| B 日付 | オブジェクトのキー | 実在日付を検証し `YYYY-MM-DD` へ正規化 |
| C/D/E 勤務 | `work` | 丸が1つなら `出社` / `在宅` / `休日`。全欄空なら `""`。複数選択はエラー |
| F 子供 | `kids` | 丸記号 → `true`、空欄 → `false` |
| G スタンディング | `standing` | 数値型。現行UIの範囲5〜20の整数であることを検証 |
| H スクワット | `squat` | 丸記号数×5の数値 |
| I 足踏み | `march` | 丸記号数の数値。現行範囲0〜2を検証 |
| J プランク | `plank` | 丸記号数×30の数値 |
| K 散歩 | 4散歩フィールド | 散歩パーサーで各項目へ分解。存在しない値は `""` |
| M 体重 | `weight` | 空欄は `""`。数値は数値文字列 |
| N 体脂肪率 | `bodyFat` | 空欄は `""`。数値は数値文字列 |
| O 基礎代謝 | `basal` | 空欄は `""`。数値は数値文字列 |

**コードで確認済み：** `standing`、`squat`、`march`、`plank` は数値型、散歩と身体3項目は文字列で保存します。身体項目は未入力 `""` と明示的な0 `"0"` を区別します。

**設計案：** Excel身体値は有限数であることを検証し、数値文字列へ正規化します。空セルは `""`、0は `"0"` とします。セルの見た目の書式や単位は値に混ぜません。

### 丸記号

- **確認済み：** 調査対象には U+3007 `〇` と U+25CB `○` の両方が使われています。
- **設計案：** セル全体が `〇` または `○` の連続だけで構成される場合に限り、各記号を同じ1回分として数えます。空白除去後に数え、別文字・不明記号はエラーにします。
- **設計案：** スクワットは丸数×5、足踏みは丸数、プランクは丸数×30とします。運動列の空欄は0として変換できますが、日付行全体が空欄なら保存レコードを作りません。
- **未確認・要決定：** `◯`、`●`、注釈付き丸などは、実例を確認するまで同義扱いしません。

## 3. 日付変換仕様

### Excel

- **確認済み：** 日付セルはExcel日付シリアルとして格納され、セル書式で月日表示されています。調査対象ブックは1900年日付方式です。
- **設計案：** Excel読込時はブックの日付方式（1900/1904）を尊重してシリアル値を日付へ変換します。シリアルをUnix時刻やJavaScriptのUTC日付として直接扱いません。
- **設計案：** 年・月・日を取り出して実在日付を検証し、`YYYY-MM-DD` を作ります。曜日列Aを日付判定に使いません。

### CSV

- **未確認：** Numbersから書き出したCSVの実形式、文字コード、地域設定は未調査です。
- **設計案：** CSVの日付は形式を限定して解析します。候補は `YYYY-MM-DD`、`YYYY/M/D`、`M/D/YYYY` などですが、採用形式は実データ確認後に決定します。
- **設計案：** 年なしで曖昧な日付、存在しない日付、複数解釈ができる値は推測せずエラーにします。

## 4. 項目の値変換と散歩テストケース

### 散歩パーサー方針

**設計案：** 数字＋単位で項目を認識し、順番は任意にします。距離（`km`）、歩数（`歩`）、時間（`分`と任意の`秒`、`秒`のみ、または`分:秒`）を対象にします。空白、カンマ、または単位境界を区切りとして扱い、単位の前後に空白がない形も許容します。

各項目は任意で、未入力は `""` のままとします。入力全体を消費でき、各項目が最大1回で、値域が妥当な場合だけ自動変換します。秒は0〜59の整数、距離は有限の非負数、歩数・分は非負整数とする案です。未知文字、重複単位、余分な数字、負数、小数歩数、範囲外秒はエラーとし、部分変換しません。

## 5. 未記録日・移行期間の判定

- **設計案：** 開始日・終了日は利用者が指定し、初期検証期間は候補にとどめて移行時に変更可能とします。
- 期間外の行は取り込まず、除外件数だけをプレビューに示します。
- 日付以外の移行対象項目が全て空欄なら未記録とし、保存レコードを作りません。
- スタンディング10だけの行は、初期値と実入力を区別できないため未記録と断定せず確認対象にします。
- 運動または身体のどちらかに実値がある日付だけを候補とし、同じ日付の両方の値は一つのレコードへ統合します。
- 日付行が存在しない日を自動生成・保存しません。
- **実データ確認方針：** 実データに基づく件数・未記録判定の詳細はローカルの検証結果だけに残し、公開設計書には記録内容と結び付く日付を記載しません。

## 6. 重複・競合の扱い

| 分類 | 判定案 | 推奨処理 |
|---|---|---|
| 新規日付 | 既存保存マップに日付キーがない | 追加候補 |
| 完全一致 | 正規化した変換後の値が既存値と一致 | 変更せず一致件数を表示 |
| 内容相違 | 同じ日付キーがあり値が異なる | 自動上書きせず、日単位でスキップ／明示置換を選択 |
| 初期値のみの可能性 | 既定値に近いが入力意図を判別できない | 競合として表示し、手動確認 |
| 変換エラー | 日付・型・値・散歩の検証不合格 | 保存候補から除外し、行・列・理由を表示 |

**設計案：** 比較時は現行既定値を使って不足キーを正規化します。身体・散歩の `""` と `"0"` は異なる値です。Numbersの空欄は既存値の削除指示ではありません。項目単位の自動マージは避け、日単位で既存維持または利用者が明示した置換を選びます。

**注意：** 現行アプリでは日付切り替え時に既定値だけのレコードが保存される場合があり、入力済みかどうかを示すフラグはありません。既存日付を自動で新規扱いしないことが安全です。

## 7. バックアップ・復元との共通化方針

**設計案：** JSONバックアップとNumbers移行の入力アダプターは分け、出力を共通の日付別候補レコードへ変換します。その後の検証・競合・保存を共通化します。

共通パイプライン：

1. 日付別候補レコードの生成
2. 日付・項目名・型・範囲の検証
3. 既存マップとの日単位比較と分類
4. エラー・追加・一致・競合件数のプレビュー
5. 利用者の選択を反映した候補全体の作成
6. 事前バックアップの保存確認
7. 一括保存と読み戻し後の件数・内容照合

個別アダプター：

- **JSONバックアップ：** 形式名・版・記録マップを解析し、版対応と構造を検証。
- **Numbers Excel/CSV：** シート・列見出し・日付セル・丸記号・散歩文字列を解析し、既存フィールドへ変換。

localStorageの既存キーと日別レコード構造は維持し、バックアップファイルには独立した形式バージョンを持たせます。

## 8. Git管理とデータ安全性

- 元Excel、実データCSV、日付と値が対応する検証一覧・ログはGitに追加しません。
- **実データを使うテストはGit管理外のローカルフォルダーで実行**し、公開リポジトリには架空データのテストだけを置きます。
- `.gitignore` は現状存在しません。必要な除外ルール案は `/private-numbers/` と `/private-validation/` です。実ファイル・検証ログはこれらの専用フォルダーに置きます。
- 拡張子だけの `*.csv`、`*.xlsx` 除外は、将来の架空テスト用ファイルまで除外するため推奨しません。特定の実ファイル名を除外する場合も、実ファイルをルートや一般のテストフォルダーへ置かない運用と併用します。
- 実装時は既存データを書き換える前にバックアップを利用者が保存できるようにします。
- 読込・変換・全体検証・競合選択が終わるまでlocalStorageへ書き込みません。
- 候補全体をメモリ上で作り、既存キーを先に削除せず保存します。保存後は同じキーから再読込し照合します。
- 保存失敗時は既存データを消去せず、理由と対処方法を表示します。
- localStorageの容量・保持期間は環境依存です。Safariとホーム画面Webアプリの保存領域が異なる場合も考慮し、双方で実機確認します。

## 10. 実装時に必要なテスト

### 変換と検証

- 架空データでExcel列見出し・位置、Excel日付シリアル、CSV日付形式、閏日・年またぎ・不正日付を確認。
- U+3007 `〇`、U+25CB `○`、複数個、空欄、混在・未知記号を検証。
- 丸数からスクワット5回、足踏み1回、プランク30秒となることを検証。
- 勤務区分の単一選択・複数選択エラーと、子供項目の独立性を検証。
- 上記W01〜W23をすべて自動テストし、散歩の分・秒・距離・歩数と全入力消費を照合。
- 未知単位、重複単位、余分な文字、範囲外秒、負数、小数歩数は保存候補にならないことを確認。
- 身体数値→文字列、空欄→`""`、明示0→`"0"`を確認。
- **実データ照合は別途、Git管理外で実ファイルの散歩23件すべてを照合**する。公開テスト成果物には実記録を含めない。

### 期間・競合・保存

- 期間境界、範囲外行、完全空欄行、日付行なし、スタンディング10のみを確認。
- 運動・身体の同日統合と、片方が空欄でも他方を保持することを確認。
- 新規、完全一致、内容相違、初期値のみの可能性、変換エラーの分類を確認。
- 空欄で既存値を消さず、明示0は値として残すことを確認。
- プレビューをキャンセルした場合にlocalStorageが変わらないことを確認。
- 保存失敗・容量超過で削除や部分反映を行わないことを確認。
- 保存後に同じキーを再読込し、件数・代表値・日付範囲を照合。
- JSONバックアップ復元にも共通の検証・競合・プレビュー・保存後照合を適用。

### iPhone実機確認

- Safariとホーム画面アプリの両方でファイル選択・保存先を確認。
- プレビュー、競合選択、キャンセル、完了通知を確認。
- 復元後にアプリを開き直し、保存記録とNumbersコピー機能を確認。
